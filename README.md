# BibliNum: A Dataset for Evaluating VLMs for the Automatic Extraction and Structuring of Metadata from Heritage Scientific Documents

This repository shares the annotations for the BibliNum dataset. 

*Keywords: visual document analysis, digital humanities, vision-language models, structured annotation*

## Context
The aim of this project is to develop a dataset for evaluating tools that automatically annotate scientific books. More specifically, the objective is to extract the following metadata fields from the title pages of historical scientific documents in a structured format: title, author, volume number, publisher, place of publication, and date.

__Corpus:__ The documents consist of title pages from nineteenth- and twentieth-century scientific books held in the Maison de la Chimie collection. Scans of these documents are freely accessible through the Gallica portal. Most of the books are in French, but other languages are also represented, including German, English, Italian, Russian, and Swedish.

__Challenge:__ The automatic extraction of metadata from digitized heritage documents is affected by various sources of error. These include physical deterioration of the original material, historical typefaces, stamps or handwritten annotations added to the document, and the absence of certain fields due to layout choices. Scan quality also varies.

__Content:__
The present dataset documents these sources of error. It consists of an annotated collection of title pages with manual annotations for six fields—title, author, volume number, publisher, place of publication, and date—covering the presence, content, and legibility of each field.

One distinctive feature of the proposed dataset is its combination of three annotation sources:
* Metadata taken from the book’s Gallica bibliographic record. This metadata was produced by expert librarians and often contains more detailed information than appears on the document itself, such as the author’s full name.
* Pre-annotations generated by prompting a vision-language foundation model, Gemma-31B.
* Manual annotations consisting of a faithful transcription of the content of the six selected fields.

The BibliNum dataset can be used to evaluate automated visual document analysis systems. In addition, annotations concerning the presence and legibility of fields make it possible to determine whether a model hallucinates content when the relevant information is absent from the image. They also help identify and understand the sources of model errors when particular fields are difficult to extract.

## Annotation Guidelines
Instructions for manual annotation.

__General Instructions__

Transcribe exactly what is written on the document. Preserve uppercase and lowercase letters.

__Field-Specific Instructions__

1. (a) Title
* When the distinction between the title and subtitle is ambiguous, select the longest possible title.
1. (b) Subtitle
* Edition statements are not considered subtitles. For example, "Wholfeile Ausgabe" and "FÜNFTE NEU BEARBEITETE AUFLAGE" are not considered subtitles.
* An exception is made for the following edition statement, which recalls the original title of the work: "Zweite Auflage der 'Tabellen der Kohlenstoff-Verbindungen nach deren empirischer Zusammensetzung geordnet’".
* Examples of subtitles include:
-  "FÜR ANFÄNGER UND GEÜBTERE" (for beginners and more advanced readers);
-  "FÜR STUDIERENDE AN DER UNIVERSITÄTEN UND TECHNISCHEN HOCHSCHULEN" (for students at universities and technical colleges).

2. Volume Number
* Transcribe the volume number exactly as written, without normalization or conversion into digits. For example, retain "Dritter Band" (third volume).
* Do not confuse the volume number with the edition number, which may be indicated by expressions such as "Dritte Ausgabe" or "Zweite Auflage" (edition or version numbers).
* Part numbers are accepted as volume numbers. For example, "Dritter Theil" (third part) and "ZWEITE HÄLFTE" (second half) are treated in the same way as "Zweiter Band" (second volume).
* Multi-level numbering must also be accepted and transcribed. For example, "ACHTER BAND, SECHSTER THEIL" (eighth volume, sixth part). Separate the different numbering levels with a comma.

3. Author
* Transcribe the author’s name exactly as written, without normalizing the order of the given name and family name and without expanding abbreviations. For example, an author shown as "M. M. RICHTER" on the document must be recorded exactly as "M. M. RICHTER". In the Gallica record, by contrast, the name is normalized and expanded as "Richter, Max Moritz".
* When there are multiple authors, record the principal author first. List the others in their order of appearance, separating each name with a comma.
* For example, for works described as originating from "C. G. J. JACOBI" and arranged by "K. WEIERSTRASS", record "C. G. J. JACOBI, K. WEIERSTRASS".
* Another example is: "JUL. WILH. BRÜHL, EDVARD HJELT, OSSIAN ASCHAN, O. COHNHEIM, O. EMMERLING, E. VAHLEN".

4. Publisher
* Extract only the name of the publisher or, when an individual publisher is not given, the name of the publishing house.
* For example, for "VERLAG VON WILHELM ENGELMANN", retain only "WILHELM ENGELMANN".
* "VERLAG DER DIETERICHSCHEN BUCHHANDLUNG" is accepted as a publisher value.

5. Place of Publication
* When multiple cities are listed, preserve the wording exactly as written. For example, retain "Leipzig und Heidelberg".

6. Date
* The date is generally unambiguous.

```
        },

        },

            "cause": "absent"
        },
        "_note": "Page de titre partiellement masquée par un ex-libris."
    }

```

__Legibility__

This field is mandatory for every annotated entry.

Value	Meaning
Lisible	The field is visible in the image, and the extracted value is plausible.
Non lisible	The field cannot be read reliably.

Cause of Illegibility
This field is present only when lisibilite is set to Non lisible.
Value	Meaning
qualite	The field is present but is blurred, overexposed, too dark, or displayed at insufficient resolution.
recouvert	A stamp, sticker, deletion mark, or another element physically obscures the content.
manuscrit	The field is handwritten and is illegible or ambiguous.
absent	The field is not present on the document.
Correction

This field is optional. It may be included regardless of legibility when the value extracted by Qwen is incorrect or incomplete.
* The corrected value replaces the Qwen value directly in the corresponding JSON field. For example, metadata.date contains the corrected value.
* The correction is also recorded in _annotations under the "correction" key, making it possible to measure the model’s error rate.
* When the field is absent from the document, the correction is an empty string: "".

__General Note__
The optional _note field is located at the top level of _annotations. It contains free-form comments concerning the image as a whole, such as reading ambiguities or special cases.
 
Fields Excluded from Annotation
The image_filename and processing_time_seconds fields are technical fields and do not appear in _annotations.
 
Annotation Tool
The annotations were produced using a Streamlit interface developed for this project (annotateur2000.py).
The interface displays each image alongside its extracted fields. It allows annotators to:
* assess the legibility of each field;
* specify the cause of illegibility;
* correct inaccurate values;
* automatically resume annotation from the first unprocessed document.
